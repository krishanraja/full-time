# Codex lane

Claude directs, Codex makes (ai-harness `tool-router`, "Creative production"). Ruling (Krish, 2026-11-01): Codex makes
this venture's assets, motion design and animation, and no session asks him how to reach Codex, to open a command line
or to say Codex is done.

Codex runs only on Krish's home computer, inside WSL Ubuntu. That computer's recordings pass (content-engine
`scripts/velib/codex_lane.py`, `config/codex-lanes.json`) checks this repository every five minutes for a card in
`codex/queue/`, builds it, and pushes the result back. A session queues work like this:

1. **Write the card** at `codex/queue/<id>.md`, where `<id>` is lowercase words joined by hyphens. Use the template
   below. Name every input file it may read and every path it may write; Codex has no tool connections, so any Runway
   or Higgsfield clip or still it needs is generated by Claude first and committed as an input.
2. **Book it.** Call Control Center's `reserve_credit_spend` (engine `growth-fulltime`, pool `codex`, amount the card's
   expected allowance points, 1 if unsure) and put the returned id in the card as `spend_id`. Without a booking
   the computer refuses the card. A refusal (`no_pool`, `held`, `over_share`) is Krish's placement to change in
   Control Center: say so in one line, do not queue.
3. **Push it** on main or this session's `claude/` branch. Codex's worktree is cut from that branch.
4. **Read the result** from the branch `codex/<id>`: `git fetch origin codex/<id>`, then
   `codex/results/<id>.json` says `ok` and any problems. That branch holds Codex's work; re-run the acceptance
   yourself, look at the visual output, then merge it into your branch or open a pull request from it.
5. **Settle** the booking with `settle_credit_spend` (the actual cost; 0 if it failed).

A card is built once: the branch `codex/<id>` marks it done. To run it again, use a new id.

## Card template

```markdown
---
card: <id>
title: One line naming the asset
spend_id: <the id reserve_credit_spend returned>
max_minutes: 40
max_calls: 40
write_allow: [path/to/output/*, another/file.ts]
---
## Goal
What to make, for whom, and the one point it must land. The creative direction Claude signed: references, colours,
type, timing, and the exact input files.

## Acceptance
pnpm test path/to/test
node scripts/check-something.mjs

## Return
What Codex reports back: the files it made and anything it could not do.
```

Acceptance lines start with `pnpm`, `npm run`, `npx`, `node` or `python3`; anything else is ignored.
